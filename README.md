# 外卖平台指标监测仪

一个面向经营分析场景的浏览器仪表盘：导入订单 CSV，按月计算指标，用简明经营小结说明变化，再按需要查看图表和数据质量明细。

**体验方式：**打开部署后的网页，点击「载入合成演示」；也可下载空白模板，整理并导入自己的订单 CSV。演示订单均由程序合成，不代表真实企业数据或实际经营成果。

## 这个项目解决什么问题

订单数据分散、计算口径容易混淆、图表难以快速阅读。本项目将指标定义、数据校验、趋势拆解与经营观察放在同一工作台，优先展示「本月发生了什么、应先观察或排查什么」。

## 主要功能

- **经营总览：**以订单原金额为规模北极星，辅助展示订单量、客单价和佣金收入。
- **月度经营小结：**区分平稳、上升和下降，展示变化线索与第一步建议。±5% 是默认可调观察阈值，不是统计显著性判断。
- **可比窗口：**推定完整月份比较整月总额；不完整月份比较上月同日范围。数据不足、缺少上月数据和存在阻断问题时单独提示。
- **下单需求：**突出下单人数与人均下单频次；小时图标注最高、最低时段；日用户图标注最高、最低和平均值，支持并列极值。
- **餐厅与用户：**查看有单餐厅订单分布、餐厅交易覆盖、窗口内复购率与购买/售后四类画像。
- **数据质量：**检查字段缺失、重复订单、日期与数值错误、未知优惠等；先展示问题数量和类型，再按需展开详情。
- **交互：**五个分析板块悬停或点击切换；指标口径悬停显示；蓝色视觉风格，数字与英文使用 Times New Roman。

## 核心口径与业务边界

| 指标 | 计算方式 |
| --- | --- |
| 订单金额 | 订单原金额之和；不是平台净收入 |
| 客单价 | 订单金额 / 唯一订单数 |
| 下单结构 | 订单量 = 下单人数 × 人均下单频次 |
| 复购用户率 | 观察窗口内至少 2 单的用户 / 全部下单用户 |
| 退款/拒付涉及订单率 | 合并金额 > 0 的唯一订单 / 全部订单 |
| 退款/拒付金额占比 | 合并字段金额之和 / 订单原金额之和 |

月度金额变化采用「人数 × 频次 × 客单价」的三因素数学分解；建议是排查与试验方向，不能证明因果。没有访问数据，不计算访问 UV 或转化率。有单餐厅不等于在线营业供给。佣金减优惠、配送费、手续费和退款/拒付仅作费用归属假设下的贡献利润情景，不称实际净利润。

观察边界由上传文件的最早、最晚有效订单推定，不能保证上传完整。中间缺单日暂按零单；不外推未覆盖日期。月度涨跌判断要求两期至少各 7 天、20 单。日均用户数按每日去重人数之和除以观察天数，不用整月去重用户数直接相除。

## 本地打开与修改

直接双击根目录的 `index.html` 即可体验，无需安装依赖。演示数据已内嵌，因此本地打开也能载入。

源码在 `src/`。修改后，在项目根目录执行以下命令，重新生成用于展示的 `index.html`：

```text
python scripts/build.py
```

可选检查（已安装 Node.js 时）：

```text
node tests/smoke.cjs
```

技术实现为 HTML、CSS、原生 JavaScript 与 SVG；计算在浏览器本地完成，没有后端、外部图表依赖或数据上传接口。CSV 仅保留在当前页面内存中，刷新后需重新导入；本项目不提供后台定时采集。
